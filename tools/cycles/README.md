# Full-layer cycle validation

For the selected complete small-model layers, use the compiled four-state XSim runner. It retains the complete Verilog golden calculation and every final output/cycle/phase/transfer check:

```sh
python3 tools/vivado/rtl_validate.py --vivado-root /opt/AMD/Vivado/2026.1 --variant all --out-dir runs/rtl-xsim-prepare --prepare
python3 tools/vivado/rtl_validate.py --vivado-root /opt/AMD/Vivado/2026.1 --variant all --out-dir runs/rtl-xsim
```

This is RTL-only simulation, separate from synthesized-netlist native-SAIF power. The accelerator sources are unchanged. The generated bench moves declarations for XSim compatibility, adds stage timing/progress markers, and uses a cycle-based watchdog. Full independent Verilog reference calculation, unknown/output checks, six exclusive cycle phases and nested accounting remain enabled. Stage timings measure host execution time; Tcl pauses do not advance simulated time. RTL clock remains10ns; native power capture uses actual1MHz. Timing simulation is functional, with no physical timing-closure claim.

The public runner processes selected cases sequentially for portability; the reported experiment used memory-bounded independent architecture workers with isolated compiled snapshots and a single result writer. Host concurrency does not change simulated cycles.

The Icarus runner below is retained as an alternate replay path and for small examples; host runtime depends on the selected layer.

From the repository root:

```sh
python3 tools/cycles/run.py --variant all --out-dir runs/cycles --prepare
python3 tools/cycles/run.py --variant NHWC --layer cifar10_conv1 --out-dir runs/cifar10-nhwc
python3 tools/cycles/run.py --variant all --out-dir runs/cycles-all --timeout 259200
```

Requires Python3 and Icarus Verilog. Use IVERILOG_BIN, VVP_BIN and optional IVERILOG_BACKEND to select installed binaries/runtime files. Output folders must be new. Full layers are expensive; the generous wall timeout is distinct from the testbench cycle watchdog.

The runner verifies source and fixture hashes, compiles the exact tiled bench, computes the full independent Verilog signed32 reference, checks every output against both that reference and the immutable golden fixture, and requires accepted cycles, phases, tile/core/tap-job counts, ordered-transfer signature and nested counters. The supplied-tensor run_case.py also offers the retained Python course golden calculation. Fixtures are generated by the retained Python integer golden; the Verilog calculation supplies the independent full output check.

Exclusive planning/input/kernel/core/output/transition phases sum exactly to the accepted-start-through-final-store cycle count. Nested core im2col/weights/advances/stalls/transitions describe core work; retries overlap and must not be added. External reads/writes and tile/reduction core-job counts explain traffic and repeated setup. Simulation does not establish physical timing closure. Only the four selected N1 tiled cases per design belong to this performance study; existing batch correctness is reused without a new batch sweep.
